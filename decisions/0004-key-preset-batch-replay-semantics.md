# ADR-0004: 键盘预设切换采用"整批重放"，不做增量 diff，用户自定义被覆盖属预期行为

- 状态: accepted（**既有决策的事后重建**，来源：`HardwareKeyProfiles.applyProfile` 结构 + README"切换预设会覆盖自定义键位"的用户告知）
- 日期: 2026-07-21

## 背景
五套机型预设本质是"一组 `ManagedPreference` 的目标值集合"。
用户可以在预设基础上自定义个别键位。切换预设时面临两种语义：
- 增量：只改与目标预设不同的项 → 保留自定义，但"当前到底处于什么键位状态"失去单一事实源，
  出现"预设 A 的候选键 + 预设 B 的动作键"的混合态，调试与用户心智都混乱
- 整批重放：把所有相关偏好批量设为目标预设值 → 状态永远可预测，代价是覆盖自定义

## 决策
整批重放。`applyProfile` 是唯一事实源（`HardwareKeyProfiles` 内
`keyBindings`/`shortcutValuesFor`/`candidate2to5` 三处清单必须同步维护），
覆盖行为在 README 与设置页显式告知用户。

## 后果
- 好处：任意时刻键位状态 = 当前预设 + 其后的手动修改，可完全推演；
  机型间切换无残留（避免 Titan2 的 Tab 选字键"漏"到 Q25 上）
- 代价：用户自定义易失 → 新增预设/键位时**必须同步三处清单**，漏一处 = 该键位在切换后行为漂移
- 未来若需求变为"预设 + 保留自定义"，需立新 ADR 引入 per-key 的 custom-overrides 层，
  届时匹配优先级改为 custom > profile
